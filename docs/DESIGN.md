# 最小版本设计与取舍

状态：描述 MVP 0 和 2026-11-27 的 MVP 1（启动扫描、变化历史、本地只读 MCP），附列尚未满足的验收条件。不是已承诺的大型产品规划。决策依据见 DECISIONS.md。

## 输入和输出

输入是游戏公开给插件的角色状态。输出是本地 UTF-8 JSON 和控制台文本，包含角色、当前任务及目标进度、可用时的已完成任务、位置、已穿装备、时间与新鲜度。

背包、银行、拍卖、天赋、专业、配方、任务路线规划和自动决策不属于当前最小采集范围。游戏任务字符串属于数据，后续 AI 不应将其视为可执行指令。

## 主要设计决定

### 保留本地日志传输

SavedVariables 通常依赖登出、退出或重载才能落盘，无法满足持续自动更新。已审阅的 ForeverSync 证明其方案使用系统消息加聊天日志，最终本项目也在实际客户端验证了这种传输。

代价是游戏会记录其他聊天，且需要填充推动落盘。本项目只提取自有行，不自动删除用户的原始日志。该技术验证不等于官方政策背书。

### 使用独立最小插件

ForeverSync 0.14.0 的 ID/计数输出对其规划网站合适，但缺少用户要求的完整中文文本和已穿装备。另写 LocalContext 更直接，避免安装额外规划 UI 和导出不需要的数据。未复制其 GPL 实现。

### PowerShell 而非必需 Python

Windows 已有 PowerShell 5.1，可减少安装负担。Python 和 lupa 只用于开发模拟测试；不是运行依赖。现有测试脚本的中文源文件编码与 PowerShell 5.1 存在注意事项，见运行手册。

### 完整快照而非增量协议

每个快照独立包含所需字段。掉一个完整快照时，下次可以恢复，不需维护跨消息任务增量状态。代价是重复传输已完成任务和装备，日志量较大。

### 分段十六进制封包

JSON 的 UTF-8 字节转 hex，避免日志文本切分和中文解码影响传输。每段 700 个 hex 字符，分段带 session/sequence/index/count。没有压缩、密码学签名或传输认证；这是单机日志协议。

### 15 秒采样和战斗暂停

用简单周期采样代替大量事件处理。战斗开始前不启动新快照，降低运行负担；已经排队的消息不会因为随后进入战斗立即取消。15 秒不是实时性服务保证。

### AI 连接层：本地只读 MCP（D1、D8、D12）

桌面客户端（Claude Desktop、ChatGPT 桌面客户端的 Codex 设置、Codex、Claude Code）在本机启动 `mcp-server.ps1`，通过 stdio 读取 player.json 和 history.jsonl。不联网、不开端口、不上云。服务器用纯 PowerShell 实现，游戏电脑无需安装其他东西。每次调用重新计算数据年龄，游戏文本作为数据返回。

不做：网页版 ChatGPT、手机访问、云盘同步、隧道、跨电脑实时服务。GitHub 不是游戏状态实时总线。

### 变化历史只记变化（D9）

history.jsonl 只在等级、区域、任务、装备变化时追加，最多 500 行，让 AI 能回答“刚才发生了什么”。坐标移动不触发。

### 启动只取最新快照（D3）

读者从日志末尾扫描，只发布最新完整快照，避免把重放的历史数据交给 AI。

## 明确不作出的保证

不保证所有 Forever 版本、所有本地化或副本限制都兼容；不保证任务列表完整；不保证战斗中更新；不保证停止读者会关闭聊天日志；不保证已有流程能应对所有日志轮转/文件替换。上述内容必须通过单独实现和验证后才能改为“支持”。
